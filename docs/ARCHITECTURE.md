# PIRCAD — architecture

**P**hysics-**I**nformed **R**oot-**C**ause disambiguation and **A**daptive-response
**D**ecision framework for trusted IoT sensing at the fog layer.

This is Generation 2 of the FHAD work. Generation 1 answered *"is this sample
anomalous?"*. Generation 2 answers *"why is it anomalous, and what should the
system therefore do differently?"* — and the second question is the one that
turns out to have engineering content.

---

## 1. Why the architecture changed

The Generation-1 pipeline was

```
sensor ──► rolling-mean detrend ──► CUSUM ──► (if flagged) Isolation Forest ──► filter ──► cloud
```

Every stage of that is a known technique, and the patentability search found all
five extracted features disclosed across four prior-art documents. More
importantly, the pipeline could not actually do what its title promised: nothing
in it distinguishes *sensor drift* from *data poisoning*. Isolation Forest labels
a window abnormal; it does not say why, and the system does the same thing —
discard — either way.

Discarding is the wrong response to both:

* A drifting sensor is still a working sensor. Throwing its data away loses
  coverage when the correct answer is a calibration correction.
* Poisoned data must not merely be dropped. It must be kept out of every adaptive
  element in the system, or the attack gets absorbed and the detector is
  afterwards blind to genuine faults.

## 2. The pipeline

```
                         ┌─────────────────────┐
                         │   physical process  │
                         └──────────┬──────────┘
                                    │  measurements + actuation commands
                                    ▼
   ┌────────────────────────────────────────────────────────────────┐
   │                          FOG NODE                              │
   │                                                                │
   │  E8ᵢ  standing calibration correction (bounded, audited)       │
   │            │                                                   │
   │            ▼                                                   │
   │  E1   process model / digital twin ──► expected response       │
   │            │        (dedicated-observer scheme)                │
   │            ▼                                                   │
   │  E2   residual = measured − expected  ──► character features   │
   │            │                                                   │
   │            ▼                                                   │
   │  E3   lightweight statistical trigger on the residual          │
   │            │  ~1–5 % of samples in nominal operation           │
   │            ▼                                                   │
   │  E4   cross-sensor physical-consistency graph                  │
   │            │  instrument-side  vs  process-side                │
   │            ▼                                                   │
   │  E5   root-cause disambiguation + confidence                   │
   │            │  {normal, drift, poisoning, process event}        │
   │            ├──────────────► E6 confidence gate ──► escalation  │
   │            ▼                        (asynchronous, optional)   │
   │  E8   differential response          E7 adaptation governor    │
   │        drift  → recalibrate, keep forwarding                   │
   │        poison → quarantine, freeze adaptation, security alert  │
   │        process→ forward + alarm, calibration forbidden         │
   └────────────────────────────────────────────────────────────────┘
                                    │  selectively forwarded data
                                    ▼
                              cloud analytics
```

## 3. The elements

### E1 — expected-response generation (`twin.py`)

The measurement is compared against what the **monitored physical process** says
it should have been, not against its own recent history. Any model producing that
expectation qualifies — first-principles process model, digital twin, state
estimator, learned physics-constrained relation.

Two things about the implementation matter.

**Dedicated-observer structure.** Each channel's expectation is generated by a
state estimate that *excludes that channel*. This is not cosmetic. A single
closed-loop estimator tracks its own measurements, so the innovation of a slowly
biased channel stays at the noise floor and the bias never appears — exactly the
blind spot a slow false-data injection exploits. With one estimator per channel,
anchored on the other instruments plus the process dynamics, a bias appears in
its own channel's residual at full amplitude and grows without bound.

```
expected(T_in)  ← P, RH, thermal dynamics
expected(P)     ← T_in, RH
expected(RH)    ← T_in, P
expected(T_amb) ← energy balance:  T_in − Q·duty/k
```

**Governed adaptation.** The estimator is re-anchored only on channels the fog
node currently trusts, with weights supplied by E7 and *slewed* rather than
switched (a step change in one anchor's weight re-partitions the estimator and
shows up as a jump in every other channel's residual — chatter the trigger would
read as a fault).

### E2 — residual generation and character features (`residual.py`)

`r[k] = measured[k] − expected[k]`, normalised by statistics learned on a clean
commissioning window and then **frozen**. An adaptive scale is precisely the
handle a slow injection uses to normalise itself away.

The feature set separates *causes*, not magnitudes:

| feature | what it encodes |
|---|---|
| `slope_ratio` | growth rate against the transducer's ageing envelope |
| `monotone_frac` | ageing bias is smooth and one-directional |
| `corner`, `jump_max` | an injection has an onset — a discontinuity ageing cannot produce |
| `acf_shift`, `var_ratio`, `flatness`, `hf_ratio`, `kurt_incr` | a drifting transducer still observes the real process, so its innovation statistics are preserved; a substituted stream carries the attacker's noise |
| `dyn_coherence` | whether the reported stream still follows the modelled micro-dynamics — see below |

**`dyn_coherence`** is the correlation between the residual's increments and the
model-predicted increments, negated. A healthy-but-drifting sensor still tracks
the modelled dynamics of the plant, so its residual increments are uncorrelated
with the predicted ones (measured: −0.036). A substituted stream does not follow
the real micro-dynamics, so its residual increments become the *negative* of the
predicted increments (measured: +0.430). Forging this requires a real-time, exact
model of the plant and of the controller's switching phase — a materially harder
attack than producing a plausible number.

**These features are individually redundant and collectively necessary**, and the
ablation says so plainly. Removing `dyn_coherence` alone costs almost nothing
(0.963 → 0.962), because the noise-signature and onset features carry the same
information by a different route. Removing the whole character group costs a great
deal (→ 0.877, with injections misread as drift rising from 0.000 to 0.093). So
`dyn_coherence` is the most *legible* discriminator — it is what makes the
physical argument in one line — but it is not the load-bearing one. Redundancy
across several independent physical signatures is the property that matters, and
it is also what makes the design robust to an attacker who defeats any single one.

### E3 — statistical trigger (`triggers.py`)

CUSUM / EWMA / Page-Hinkley on the residual, plus an instantaneous spike test.
This is the only Gen-1 stage that survives structurally, and it is deliberately
demoted: it is no longer the detector, it is the cheap gate that decides when the
expensive stage may run. Because it now runs on a residual whose nominal
distribution is stationary by construction, it needs no rolling-mean detrending
and no seasonal handling. Charts restart after signalling, so a sustained
deviation produces repeated firings rather than one latched flag.

### E4 — cross-sensor physical consistency (`consistency.py`)

Answers a question orthogonal to drift-versus-poisoning: **is the deviation on the
instrument side, or has the plant itself moved?** Getting that wrong is the
dangerous failure mode of every "detect → recalibrate" system — a genuine process
excursion gets calibrated away and the system is now blind to a real fault.

Physical constraints are evaluated on the reported measurements (deliberately not
on the model's internal state, which tracks a slow bias and would hide it):

| constraint | statement |
|---|---|
| `g_gas` | `P − P(T)` — isochoric ideal gas |
| `g_humidity` | `RH − RH(T)` — conserved absolute humidity (Magnus) |
| `g_dyn` | measured `T` increment over `m` samples vs the open-loop integrated prediction |
| `g_energy` | `ema(T − T_amb) − Q·duty/k` — quasi-steady energy balance |
| `g_control` | `ema(T) − setpoint` — the loop is supposed to regulate |

Each candidate cause has a **signature**: the direction it pushes the violation
vector. Signatures come from perturbing the *model*, so no labelled fault data is
needed. Localisation is the hypothesis whose signature best explains the observed
direction, including an explicit `PROCESS` hypothesis (an unmodelled heat input)
alongside the per-channel bias hypotheses.

Two design details that were found by measurement, not assumed:

* **Sigma floors.** A constraint must not be normalised below the resolution at
  which it is physically meaningful. `g_control`'s statistical noise after heavy
  smoothing is far below the band the controller actually regulates within;
  normalising by that noise makes every instrument bias look like a loss of
  regulation. The floor was chosen by sweeping it and reading the localisation
  margins — too low and drift masquerades as a process fault, too high and a
  process fault becomes indistinguishable from a biased ambient sensor.
* **Magnitude floor.** Below a minimum violation magnitude, localisation reports
  *unresolved* rather than an arbitrary winner. Without this, a channel whose bias
  has just been successfully compensated away gets re-attributed to noise.

### E5 — root-cause disambiguation (`rootcause.py`)

Input: residual-character features plus the localisation. Output: one of
`{NORMAL, SENSOR_DRIFT, DATA_POISONING, PROCESS_EVENT, UNKNOWN}` with a
confidence. Three interchangeable embodiments — an interpretable rule classifier
needing no training data, a supervised model, and a hybrid where the physical
hypothesis test is authoritative for process-side excursions (where being wrong
is a safety issue) and the learned model resolves drift-versus-poisoning.

The invention does not depend on the classifier. Random forest, gradient
boosting, TinyML are all embodiments.

### E6 — confidence-gated escalation (`escalation.py`, `quantum.py`)

Only unresolved cases leave the fog node. Escalated samples are **held** — never
forwarded, never used for adaptation — until the verdict returns, and if it never
returns the local verdict stands. The service is asynchronous by construction, so
the backend is allowed to be slow.

An optional gate-model **quantum-kernel** backend is provided (ZZ-feature-map
fidelity kernel, exact statevector simulation here). It is explicitly *not* the
detector: it sits off the real-time path, sees only the minority of ambiguous
cases, and the architecture degrades gracefully without it. No quantum advantage
is claimed or required.

### E7 — adaptation governor (`governor.py`)

A per-channel gate in front of **every** adaptive element: the process model's
state re-anchoring, the residual normalisation statistics, the calibration
offsets, and any retraining of the root-cause model itself.

```
TRUSTED ──trigger──► WATCH ──drift verdict──► DRIFTING (sticky while compensating)
                        │
                        └──poison verdict──► QUARANTINED ──freeze hold──►
                              RECOVERING ──clean run (+ operator ack)──► TRUSTED
```

A channel that is merely *triggered* already stops feeding the process model —
before any cause has been decided — so the reference cannot be dragged while the
system is still deciding what it is looking at.

A drift verdict is **sticky**: the channel stays flagged, and its correction stays
engaged, long after the residual has been compensated away. The residual is zero
*because the correction is working*, which is evidence the correction is working —
not evidence the sensor recovered. Clearing the flag there would restart the cycle
and re-open the adaptation path on a sensor known to be degraded.

### E8 — differential response (`actions.py`)

| cause | action |
|---|---|
| benign sensor drift | bounded, rate-limited, audited calibration correction; **data keeps flowing** |
| data poisoning | quarantine, freeze adaptation, security indication, nothing forwarded |
| genuine process event | forward **and** alarm; calibration explicitly forbidden |
| ambiguous | held pending escalation; no irreversible action |

The recalibration path is deliberately conservative: a fraction of the estimated
bias, rate-limited per sample, capped in total, every adjustment audited. A
capped, rate-limited corrector cannot absorb an attack faster than the detector
can classify it.

## 4. Modelling assumptions in the testbed

The evidence apparatus (`simulator.py`) is not part of the claimed system, but its
assumptions bound what the numbers mean. Stated plainly:

1. **The control loop uses an independent temperature reference.** A drifting
   monitored sensor therefore shows up in `g_control`. Where the monitored sensor
   *is* the control sensor, `g_control` stays near zero for a sensor bias and the
   other four constraints carry the separation — the architecture is unchanged,
   the signature dictionary simply has a different `T_in` column.
2. **The stealth attacker substitutes a lagged surrogate of the process.** This is
   the standard false-data-injection model: the attacker has a model of the plant
   but not real-time exact state. An attacker who *does* reproduce the plant's
   micro-dynamics and the controller's switching phase exactly would defeat
   `dyn_coherence`; the claim is that this raises attacker cost substantially, not
   that it is impossible.
3. **Drift and injection are rate-matched by construction** in the headline
   comparison. This is deliberately the hardest case, not a favourable one.
4. Root-cause labels for non-target channels are `NORMAL` by construction, which
   is what teaches the model to stay quiet on collateral triggers.

## 5. Cost

Nominal per-sample cost is one model evaluation, four subtractions and four CUSUM
updates. The root-cause stage runs only on engaged channels, and is re-evaluated
at a configurable interval (a fresh trigger firing always forces re-evaluation, so
an isolated substituted sample is never answered from a cached verdict).
