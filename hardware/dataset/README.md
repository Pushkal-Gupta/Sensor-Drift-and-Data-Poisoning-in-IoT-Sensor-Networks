# Dataset — PIRCAD edge node

Both files are regenerated by `../run_checks.sh`; nothing here is hand-edited.

```bash
./test_edge --csv > dataset/edge_dataset.csv
python3 fog_bridge.py --replay dataset/edge_dataset.csv --config proposed \
        --out dataset/fog_decisions.csv
```

## `edge_dataset.csv` — sensor stream with labelled injections

| | |
|---|---|
| Samples | 4 620 = 3 configurations × 7 injection modes × 220 samples |
| Sampling interval | 2 s (the DHT22 minimum), so 220 samples ≈ 7.3 min per episode |
| Onset | injection begins at sample 60; samples 0–59 are clean and let the model settle |
| Source | the same `pircad_edge.h` kernel the ESP32 runs, driven on the host by `test_edge.cpp` with a fixed-seed pseudo-random noise generator, so the file is byte-reproducible |
| Split | samples 0–39 are the commissioning window in which the residual scales are learned and then frozen; 40–59 are clean hold-out; 60–219 carry the injection and are what gets scored |

Physical model behind the clean signal: ambient 24 °C with a slow ±0.8 °C
excursion and 0.05 °C RMS transducer noise. The air holds a fixed vapour
pressure (1340 Pa), so humidity is derived from the *true* temperature by the
Magnus relation. The injection is added to the temperature channel only.

### Columns

| Column | Meaning |
|---|---|
| `config` | `baseline`, `draft` or `proposed` — which decision configuration produced the verdict |
| `mode` | injection mode (see the table in `../README.md`) |
| `k` | sample index within the episode |
| `temp_clean` | true temperature, °C — **input feature, ground truth only** |
| `offset` | injected offset, °C — ground truth only |
| `temp_reported` | `temp_clean + offset`, °C — **input feature** |
| `hum` | relative humidity, % — **input feature** |
| `residual` | thermal model residual, °C — derived |
| `cusum` | trigger statistic — derived |
| `bias` | temperature bias implied by the humidity channel, °C — derived |
| `slope` | rate of change of that bias, °C/sample — derived |
| `calib` | standing calibration correction in force, °C — derived |
| `verdict` | `CLEAN`/`DRIFT`/`POISON`/`UNKNOWN` — **model output** |
| `truth` | `CLEAN`/`DRIFT`/`POISON` — **target** |
| `frozen` | 1 if adaptation was inhibited for this sample |

**Inputs the model may use:** `temp_reported`, `hum`. Nothing else.
**Target:** `truth`.
`temp_clean` and `offset` exist for scoring and plotting and are never read by
the decision path — `edge_step()` takes only the reported temperature and the
humidity.

### Class balance

| Class | Samples | Share |
|---|---|---|
| CLEAN | 660 | 14.3 % |
| DRIFT | 1 320 | 28.6 % |
| POISON | 2 640 | 57.1 % |

The imbalance is by design: four of the seven modes are attacks, because the
interesting failures are attack-side. Per-class recall is reported rather than
plain accuracy for that reason.

## `fog_decisions.csv` — per-sample fog-tier decisions

1 540 rows: the `proposed` slice of the edge dataset replayed through
`fog_bridge.py`, which runs the residual engine, trigger, governor, calibration
manager and response controller imported from `../../pircad/`.

| Column | Meaning |
|---|---|
| `k`, `mode`, `truth` | as above |
| `temp_in` | temperature as received, °C |
| `temp_out` | after the standing correction, °C — what would go to the cloud |
| `hum` | relative humidity, % |
| `residual`, `z` | physics residual and its normalised value |
| `cause` | `NORMAL` / `SENSOR_DRIFT` / `DATA_POISONING` / `UNKNOWN` |
| `confidence` | classifier confidence |
| `action` | `FORWARD` / `RECALIBRATE_AND_FORWARD` / `QUARANTINE` / `ESCALATE` |
| `forwarded` | whether the sample reached the cloud tier |
| `calib` | standing correction, °C |
| `note` | why that action was chosen |

## Reproducing the reported numbers

```bash
./run_checks.sh
```

prints the edge kernel table (baseline / draft / proposed × 7 modes) and the fog
confusion matrix. Both are deterministic.
